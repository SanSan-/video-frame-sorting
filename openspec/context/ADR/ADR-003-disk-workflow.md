# ADR-003: Общий локальный сервис и независимость файлового состояния от истории задач

## Статус

Принято.

## Контекст

CLI и браузер запускают одинаковые предметные операции. После перезапуска доступные действия должны соответствовать
файлам выбранного каталога; история выполнения нужна для диагностики, но может относиться к другому состоянию данных.

## Решение

Использовать общий прикладной сервис для обоих входов. Веб-слой управляет единственной активной операцией и ограниченной
локальной историей, показывает прогресс и восстанавливает статус прерванного исполнения после перезапуска.
Источником готовности остаются файловые артефакты и связанная транзакция; обнаружение кандидата отделено от строгой
проверки перед действием. История задач не разрешает изменение файлов.
Контракты входов, готовности и исполнения принадлежат [локальному веб-процессу](../../specs/local-web-workflow/spec.md).

## Альтернативы и последствия

Отдельная реализация для каждого входа создаёт расхождения. Состояние только в браузере теряется при обновлении;
история как источник готовности расходится с каталогом. Внешняя очередь и несколько конкурентных операций потребовали
бы распределённой координации без текущей продуктовой потребности. Один локальный процесс упрощает владение операцией,
но не даёт многопользовательского исполнения и не гарантирует продолжение работы после остановки процесса.

## Условия пересмотра

Удалённый или многопользовательский доступ, параллельные изменения каталога либо исполнение вне жизненного цикла
локального процесса.
